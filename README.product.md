# TomorrowEdge Product Guide

TomorrowEdge is the local governance and policy-evolution runtime for
heterogeneous coding agents.

## Core Thesis

The future of AI coding is not one model. It is a governed software-engineering
organization where strong agents decide, efficient agents execute, local agents
protect privacy, and humans authorize the actions that matter.

The core problem is not that models are too weak. It is that multi-agent,
multi-model engineering work is usually under-governed: budgets are opaque,
role ownership is informal, evidence is incomplete, and strong agents are used
as all-purpose workers instead of scarce decision resources.

## Product Pillars

- Agent Council Governance Runtime: high-level tasks enter through a Chief
  Agent, then council members critique, fill gaps, claim tasks, and form a
  consensus TaskGraph.
- Heterogeneous model teams: Codex, Claude Code, DeepSeek, MiMo, local models,
  mock/fixture profiles, and custom agents are replaceable capability nodes.
- Strong-agent governance: Chief, reviewer, and judge calls are treated as
  expensive decision resources under BudgetGate.
- Task ownership: every core TaskGraph node records owner agent, provider,
  model, and assignment reason.
- Full-access cockpit: autonomous patch, shell, repair, review, mutation, and
  delivery loops with visible trace.
- Capability stitching: one model can perceive, another can implement.
- External agent bridge: Codex and Claude Code can be role-bound nodes rather
  than replacements for TomorrowEdge.
- Context projection: full artifacts are preserved, compact evidence is shown
  to models.
- Policy evolution: objective-action-feedback traces and bounded Strategy
  Mutations improve orchestration policy without mutating the safety boundary.

## Product Boundary

TomorrowEdge should not become a general personal-agent runtime. It should stay
focused on engineering governance: Chief planning, council consensus,
delegated execution, evidence, budget, mutation, final review, trace, and
delivery.

Benchmarks and dashboards are useful research/evaluation tools, but they are
not the product center. Sirius makes the Agent Council path the main line.
